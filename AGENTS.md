## 📖 Project Overview
**Vagbhata** is a lightweight, highly optimized web-based audio player for listening to the **Aṣṭāṅga Saṅgraha** (a foundational text of Ayurveda written by the ancient scholar Vagbhata).
The user interface is designed to resemble traditional manuscripts, featuring warm, earth-toned colors and a clean card layout with simple audio playback functionality. It is fully static-site-generated (SSG) for optimal SEO and search crawler indexing.

---

## 🛠️ Stack & Dependencies
* **Core**: Astro 7.0 (using Vite 8 & Rolldown engine), HTML5 Audio API.
* **Routing**: Astro Client Router (`<ClientRouter />` from `astro:transitions`) enabling persistent audio playback across page transitions.
* **Styling**: Vanilla CSS (using native CSS Nesting, `@layer` cascade layers, and modern CSS features).
* **Testing**: Vitest for unit testing helper utilities.
* **External Tools**: `ffmpeg` / `ffprobe` (for automated audio duration extraction during the build step).

## ⚙️ Development Commands
Run these commands from the root directory:
* **Install dependencies**:
  ```bash
  npm install
  ```
* **Start development server**:
  ```bash
  npm run dev
  ```
  *(Note: This automatically runs `scripts/generate-chapters.js` beforehand to update chapter metadata).*
* **Build for production**:
  ```bash
  npm run build
  ```
  *(Note: Builds output static HTML files into the `dist/` directory).*
* **Preview production build locally**:
  ```bash
  npm run preview
  ```
* **Run unit tests**:
  ```bash
  npm run test
  ```

## 📁 Repository Structure
Here are the files you need to know about:

* 📄 **[astro.config.mjs](./astro.config.mjs)**: Astro configuration file. Defines static output and base path `/vagbhata`.
* 📄 **[src/layouts/Layout.astro](./src/layouts/Layout.astro)**: Master page shell layout. Handles SEO tags, preconnect optimization, view transitions, and persistent player footer bar.
* 📁 **`src/pages/`**:
  * 📄 **[src/pages/index.astro](./src/pages/index.astro)**: Homepage that dynamically groups chapters by their respective Aṣṭāṅga Saṅgraha Sthanas (sections) and provides search filtering.
  * 📄 **[src/pages/chapters/[slug].astro](./src/pages/chapters/[slug].astro)**: Dynamic route for individual chapter detail pages with rich reading text summaries and inline Schema.org `AudioObject` structured data.
* 📄 **[src/style.css](./src/style.css)**: Modern Vanilla CSS layouts and design variables (using OKLCH colors, clamp fluid typography, text-wrap, etc.). Avoid third-party styling frameworks.
* 📄 **[scripts/generate-chapters.js](./scripts/generate-chapters.js)**: Pre-build script that probes audio files in `public/audio` and writes metadata to `src/data/chapters.json`.
* 📁 **`src/data/`**:
  * 📄 **[chapters-config.json](./src/data/chapters-config.json)**: **Source of Truth** for chapter configurations (slug, title, sthana, chapterNumber, description, filename).
  * 📄 **[chapters.json](./src/data/chapters.json)**: **Generated File**. Contains final metadata with computed durations. **Do not edit this file directly.**
* 📁 **`public/audio/`**: Contains raw `.m4a` audio files. Serving them from public directory ensures clean, static, non-hashed URLs for Google Audio indexing.
* 📁 **`src/tests/`**: Contains Vitest unit tests verifying utility files, Sthana structures, and schemas.

## 💡 Guidelines & Rules for AI Agents

### 1. Data Modification (Adding/Editing Chapters)
* **Never edit `src/data/chapters.json` directly.**
* Always edit **[chapters-config.json](./src/data/chapters-config.json)**.
* Make sure to specify `"slug"`, `"sthana"`, and `"chapterNumber"` (within that Sthana) for new chapters.
* Run `npm run dev` or `npm run build` to trigger the pre-run script (`scripts/generate-chapters.js`) which updates `chapters.json` automatically.

### 2. Styling Rules
* Do not introduce Tailwind CSS or utility-first frameworks. Stick to Vanilla CSS inside **[src/style.css](./src/style.css)**.
* Maintain design token standards using OKLCH and Relative Color Syntax adjustments:
  * `--primary-color: oklch(42% 0.16 28);` (Ayurvedic terracotta)
  * `--bg-color: oklch(98% 0.01 70);` (Parchment white/cream)
  * `--card-bg: oklch(100% 0 0);`
* Keep pages fully responsive and use CSS `clamp()` for fluid layout scaling without media queries where possible.
* Use `text-wrap: balance` on headings to avoid orphans, and `text-wrap: pretty` on paragraph content.

### 3. Audio & Routing State Preservation
* Astro's `<ClientRouter />` persists DOM nodes decorated with `transition:persist`. The audio player bar (`#playerBar`) in `Layout.astro` is marked persistent.
* Make sure any page scripts listen to `'astro:page-load'` rather than `'DOMContentLoaded'` to re-bind client event listeners and sync buttons when navigating between pages.

### 4. Deployment & Build Checks
* Before committing, run `npm run test` to verify helper logic.
* Run `npm run build` locally to verify that:
  1. No TypeScript compilation errors occur.
  2. The Astro bundle builds cleanly into the `dist/` directory.
  3. `scripts/generate-chapters.js` runs successfully and updates durations.
